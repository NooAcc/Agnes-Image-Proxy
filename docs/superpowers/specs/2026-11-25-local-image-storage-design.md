# 本地图片存储设计

日期：2026-11-25

## 意图与需求

目前原图和缩略图以 BLOB 存在远程 Turso 数据库，后台相册读取图片受大数据传输和数据库网络延迟影响。本次将图片内容的主要存储改为部署机器上的文件系统。

用户已确定：

- 原图存储到 `/data`。
- 缩略图也存储到 `/data`；数据库可以保留一份缩略图备份。
- 不兼容旧代码或旧数据，允许破坏性 schema 变更，不做迁移或原图 BLOB 回退。

## 范围

保留 Go + React 单体、远程 Turso 元数据、现有 API 和鉴权模型。改变原图/缩略图保存、内容读取、删除/清空、预览与测试路径、部署和文档。不重新设计相册 UI，不增加对象存储、多实例同步、后台迁移、自动清库或定时清理功能。

## 建议实现（由实现者选择的默认值，待用户确认）

### 目录和部署

- 生产默认图片根目录为 `/data`；增加 `DATA_DIR` 环境变量，便于非容器开发。所有应用图片文件位于该目录的应用专用子目录，不删除根目录中的无关文件。
- 使用随机 `public_id` 为图片身份，文件名/分片目录完全由应用生成，不使用 prompt、上游 URL 或客户端文件路径。
- 预览使用自己的临时目录，退出后删除；测试使用隔离的 `t.TempDir()`，不写真实 `/data`。
- Compose 为 `/data` 挂载持久化命名卷；Docker 镜像预建可由 nonroot 用户写入的目录，继续使用只读根文件系统。
- 启动检查图片目录能创建且可写，不可用时明确失败，不默默切回 BLOB。
- 部署模型为单实例。本地目录与数据库必须作为同一套数据备份/恢复；不支持多个实例各用独立磁盘共享同一数据库。

### 原图保存与交付

- 移除 gallery 原图 BLOB 字段，保留数据库中的随机 public_id、MIME、字节数和其它元数据。提升 schema 版本。
- 保存原图时采用同目录临时文件、写完后原子发布，文件成功保存后才发布数据库记录/返回交付成功。
- 保持 output_key 去重语义：重复交付引用已经保存的原图，不因重试的新下载内容覆盖它；base64 与签名 URL 对应同一份权威原图。
- 文件系统和远程数据库无法跨介质事务。明确处理普通失败、重复插入和数据库结果不确定的情况：不删除可能已经成功提交的原图；允许极端崩溃/不确定提交留下不被引用的文件，不增加后台垃圾回收系统。
- 文件保存失败按图片持久化失败返回，不能返回指向不存在文件的成功链接。

### 读取与鉴权

- 管理相册原图、公开签名内容、同源参考图及 Edge 富化所需原图均读取本地文件，不读取数据库原图内容，也不重新下载上游作为回退。
- 数据库仍负责元数据、相册列表、分类、记录存在性等；本次不承诺消除所有数据库往返。普通图片内容读取至多取小型元数据，避免远程 BLOB 传输。
- 保持管理端 Bearer/Cookie 鉴权和公开端签名校验。`/data` 不作为无鉴权静态目录公开，公开签名校验失败必须在读取存储之前返回。
- 保持 GET/HEAD、MIME、Content-Length、no-store 及已删除链接失效等现有契约。HEAD 不加载完整原图内容。
- 原图缺失返回明确错误，不读取旧 BLOB；本地磁盘 I/O 错误不能被当成成功。

### 缩略图与数据库备份

- Edge 富化产出的有效缩略图落本地，并同时写入 gallery 的缩略图 BLOB 备份及其 MIME/字节数。
- 正常缩略图读取取本地文件，不查询缩略图 BLOB。
- 仅在本地缩略图缺失时读取数据库备份，尝试原子恢复本地文件；备份可读但恢复写入失败时仍可返回备份内容。不以备份掩盖权限错误等非缺失 I/O 故障。
- 缩略图内容及 MIME 一致更新；重试、并发富化不能让数据库元数据与磁盘内容对应不同版本。
- 保持现有富化状态、NSFW 标签及大小限制语义。

### 删除与重建

- 删除图片同步删除数据库记录及该图片原图/缩略图文件，清空图库处理所有应用拥有的图片文件，包括普通失败留下的孤立文件。
- 与保存/富化/恢复操作协调，防止删除后并发操作重新生成孤立文件，或清空误删新写入图片。
- 数据库记录不存在时公开链接保持 404；删除文件失败要报告，不能谎称已完全清理。
- `reset-db --confirm` 为明确破坏性操作，应同时重建应用数据库与清理应用图片目录，不碰无关目录内容。普通启动不自动删除旧数据。
- schema 不匹配时拒绝启动，用户使用空库或显式 reset-db。文档明确重建会清空账号、设置、日志及图库，没有旧图片迁移能力。

## 验证要求

- 原图只在本地、schema 无原图 BLOB，生产默认路径与可写性验证。
- 原图和缩略图读取、HEAD、签名校验、同源参考图、base64 一致性。
- 缩略图数据库备份、本地优先、丢失后的回退恢复。
- output_key 去重、数据库失败/结果不确定、文件失败、不覆盖权威原图。
- 删除、清空、重建、并发保存/富化与删除协调及只清理应用自有文件。
- 原有 Go 测试、race 检查及前端契约/构建验证；更新预览夹具和测试中的旧 BLOB 假设。
- Docker/Compose 持久化卷及非 root 写权限配置；在有 Docker 环境时实测，否则明确说明未运行镜像验证。

## 留给实现者

具体的内部文件存储接口、目录分片/文件扩展名、原子写与操作锁形式、错误映射、必要的测试辅助构造调整均由实现者决定，保持尽量小的实现面。尽可能不改对外接口，不新增依赖，优先使用 Go 标准库。
