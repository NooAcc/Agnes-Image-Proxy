# 原图存储策略与首次初始化设计

日期：2026-11-25

状态：spec 已完成，内部可实施性检查未发现阻塞问题；按用户授权自主设计，无需用户设计审阅；尚未实现

适用项目：Agnes Image Proxy（Go + React）

## 1. 目的与范围

新增 `imgbed` 原图存储策略，对接 CloudFlare ImgBed HTTP API。程序首次使用时，管理员在初始化页面选择 `local` 或 `imgbed`；配置存入 Turso，不使用新的环境变量。初始化后存储方式固定，`imgbed` 只允许修改站点地址和 API Token。

继续遵守现有交付契约：生成后下载、验证并同步保存原图，保存成功才返回本程序限时签名 URL 或原图 base64。图床是原图主存储，不是本地存储的备份。

### 用户明确决定

- 支持 `imgbed`，参考 `https://cfbed.sanyue.de/api/`。
- 上传使用 `serverCompress=false`、`returnFormat=full`、`uploadFolder=agnes-image-proxy/日期`，日期按 UTC+8（中国标准时间）计算。
- 对外保留本程序签名 URL，不直接返回图床链接。
- 新增初始化页面，在页面选择原图存储方式并填写图床连接信息，不用环境变量配置原图存储。
- 存储方式初始化后不可更改；允许更新图床地址和 Token。
- 无需用户审阅设计，由实现方自主设计。
- 允许破坏性代码/schema/API 变更；不兼容旧版本代码、数据或配置，不添加迁移、兼容分支或双写冗余。

### 本设计自行确定的细节

- 初始化位于登录之后，只覆盖原图存储，不替代现有管理密钥/Turso 启动配置。
- 日期使用上传开始时的 UTC+8（中国标准时间） 日历日期，格式 `YYYY-MM-DD`。
- 图床连接信息为站点 origin 和必填 API Token；不增加上传渠道、目录、压缩或有效期等可配置项。
- 不新增分块上传、图床文件浏览、上传测试文件、后台迁移、双存储、永久原图缓存或垃圾回收功能。
- 缩略图保留当前本地文件及数据库备份机制；这不是旧版兼容，而是两种原图策略共同使用的缩略图机制。

## 2. 当前代码与变更边界

- `internal/service/delivery.go`：受控下载、MIME/体积验证、同步保存、base64 交付。
- `internal/store/gallery.go`：原图发布、output key 幂等、图库锁、缩略图、删除及清空。
- `internal/store/image_content.go`：元数据、原图读取、签名内容和管理内容的共用存储边界。
- `internal/store/database.go`、`schema.go`：数据库及本地文件资源，schema 创建/校验/重建。
- `internal/httpapi/router.go`、`admin.go`、`auth.go`：数据面鉴权、管理鉴权、路由和会话。
- `frontend/src/app/router.tsx`、认证 guards、settings 页面、Zod 契约：新增初始化路由和已初始化状态检查。
- CLI、preview、测试 fixtures、README、OpenAPI 文档均需要同步新契约。

初始化和存储凭据独立于普通 `domain.Settings`：普通设置不得回传 Token，也不能通过整体 PUT 修改存储方式。

## 3. 首次初始化与固定策略

### 3.1 状态

采用两个持久化状态：

1. **未初始化**：存储配置表无记录。空库建表后保持此状态，不自动选择 `local`。
2. **已初始化**：存储配置表有唯一合法记录，方式为 `local` 或 `imgbed`。

记录非法、字段缺失或读取数据库失败不视为未初始化，不自动修复、默认或重新开放初始化；返回明确的服务错误。

初始化写入是一条原子 `INSERT`，数据库保证唯一性。两个并发初始化请求至多一个成功，另一个返回 `409 already_initialized`。成功后重启仍保持方式不变。

### 3.2 登录与路由

- 沿用环境变量中的 `PROXY_API_KEY` 登录；不新增无鉴权的初始化写入口。
- 新页面 `/admin/setup` 在有效管理会话内访问，位于 AppShell 之外。
- 登录成功后查询初始化状态；未初始化统一进入 setup，已初始化进入原目标页或 overview。
- 已登录管理员直接访问普通控制台页面时，未初始化重定向 setup；已初始化访问 setup 重定向 overview。
- 状态加载中显示加载状态，加载失败显示可重试错误，不靠猜测跳转或进入控制台。
- 状态查询沿用当前 Cookie/Bearer 管理鉴权、同源校验、请求体限制及 `no-store`。

### 3.3 未初始化时的后端门禁

- 会话接口、存储状态/初始化接口、静态控制台资源、健康检查与模型目录可使用。
- 其他管理 API 和生成/编辑 API 在完成其原有鉴权后，返回 `503 initialization_required`；不能通过直接 HTTP 请求绕过 UI 门禁。
- 检查必须在上游请求、图片解析产生的远程读取、容量预留和生成计费之前完成。
- 未初始化不写入图片、账号或普通设置。默认普通设置和 auth state 可由建表过程创建。
- 存储状态读取失败返回服务错误，不能误报需要初始化。
- 初始化不作为 `/health` 失败条件；`deep` 仍只检查数据库，不上传测试文件、不联系图床。

## 4. 初始化与存储设置页面

### 初始化页面

沿用现有中性色、蓝色主按钮、8px 圆角及中文表单样式，不重设计控制台。

- 标题：初始化 Agnes Image Proxy。
- 简短说明：选择原图存储方式，完成后不可切换。
- 两个具有可见标签的单选项：本地存储（`local`）、图床存储（`imgbed`）。初始不预选，要求明确选择。
- 本地模式说明原图位于 `DATA_DIR/images`，需持久化卷。
- 图床模式渐进显示站点地址输入框、密码类型的 API Token 输入框。
- 地址示例 `https://img.example.com`；提示填写站点根地址，不填文档地址或 `/upload`。
- Token 提示要求 `upload` 与 `delete` 权限，不要求 `list` 或 `manage`。
- 展示只读上传规则：不压缩、完整返回地址、UTC+8（中国标准时间） 日期目录。
- 展示提醒：选定后无法切换；图床应关闭文件自动过期；图床公开链接不受本程序签名期限控制。
- “完成初始化”按钮：未选方式、图床必填字段为空或正在提交时禁用；提交显示等待，失败保留填写内容并给出字段/请求错误；成功清除前端 Token 草稿并进入控制台。
- 这次提交本身就是对固定方式的确认，不再叠加第二个确认弹窗。

### 初始化后的设置页

新增“原图存储”区域：

- 只读展示当前方式，不提供切换控件或再次初始化按钮。
- `local` 展示本地存储说明，不提供图床字段。
- `imgbed` 展示可编辑站点地址、Token 更新框及相同的只读上传规则。
- 已保存 Token 只展示“已配置”，不展示原文、不用假掩码充当可提交的 Token。
- 更新时 Token 留空表示保留现有值；提供新值表示替换；禁止清除 Token。
- 提醒更换地址必须仍对应同一套图床文件，或管理员已在新站点准备好同路径文件；程序不迁移图片，不保留旧端点或历史 Token。
- 页面和 API 状态不得将 Token 存进 URL、localStorage、浏览器持久化 Query 缓存或错误日志。

使用关联 label、fieldset/legend、原生单选键盘行为、44px 交互目标、可见焦点、就近错误与可访问的提交状态。窄屏单列、桌面居中限宽，支持现有深浅主题。

## 5. HTTP 管理契约

新增独立端点 `/admin/api/storage`，均需要原有管理权限。普通设置 API 不接受下列字段。

### GET：查询状态及非秘密配置

未初始化返回 `200`：

```json
{ "initialized": false }
```

已初始化本地返回 `200`：

```json
{ "initialized": true, "mode": "local" }
```

已初始化图床返回 `200`：

```json
{
  "initialized": true,
  "mode": "imgbed",
  "imgbedBaseUrl": "https://img.example.com",
  "hasImgbedToken": true
}
```

响应使用判别联合；不返回 Token、空图床字段或与当前方式无关的配置。

### POST：仅首次初始化

本地请求：`{"mode":"local"}`。图床请求：

```json
{
  "mode": "imgbed",
  "imgbedBaseUrl": "https://img.example.com",
  "imgbedToken": "<具有 upload/delete 权限的 API Token>"
}
```

- 严格 JSON；拒绝未知字段、无效方式、local 附带图床字段以及 imgbed 缺少必填字段。
- 成功 `201`，返回与 GET 一致的已初始化非秘密配置。
- 已初始化始终 `409 already_initialized`，不会更新现有配置。
- 本地初始化验证本地图片目录可用；图床仅验证配置格式，不写入探测图片、不以初始化请求验证 Token 的远程权限。

### PUT：仅更新已选 imgbed 的连接信息

```json
{ "imgbedBaseUrl": "https://img.example.com", "imgbedToken": "<新 Token，可省略>" }
```

- 必须提交合法地址；Token 可省略或为空字符串，此时保留现有值；非空值按创建规则验证后替换。
- 拒绝 `mode` 和所有其他字段，不能借更新改变方式。
- 未初始化 `409 not_initialized`，local 模式 `409 storage_mode_fixed`。
- 成功 `200`，返回非秘密配置；数据库原子更新地址及 Token。
- 仅为管理员操作，不添加兼容旧端点、批量配置导入或热切换 API。

字段错误使用项目现有 OpenAI error envelope，错误不得带 Token 或原始远端响应正文。

## 6. 数据模型与资源

### 6.1 新 schema

schema 升为 **4**。仅支持空库创建和 schema 4 正常运行；schema 1/2/3 拒绝启动，管理员另行停服、备份、执行显式 `reset-db --confirm`。不自动清空用户数据。

新增 `storage_config` 单行表，纳入应用自有表清单：

- `id`：固定 1，主键和约束。
- `mode`：`local` / `imgbed`，固定不可更新。
- `imgbed_base_url`、`imgbed_token`：仅图床模式非空，本地模式为 NULL。
- `created_at`、`updated_at`。

图床 Token 服务端明文存入数据库，与现有上游账号密钥的保管模型一致。没有独立密钥管理系统时不制造“加密后密钥同库保存”的虚假保护；文档明确数据库凭据和备份属于敏感数据。

图库原图定位统一为 `original_ref`：local 存相对本地文件路径，imgbed 存解码后相对图床文件 ID（如 `agnes-image-proxy/2026-11-25/<服务端生成文件名>.png`）。保留原图 MIME、字节数、随机 publicID、output key、上游 source URL 和富化信息。

替换旧 `image_path` 字段，不保留双字段兼容；全库只有一个原图方式，不给每行增加模式/历史地址/历史 Token。缩略图字段维持其现有用途。

### 6.2 资源与边界

- 两种模式均使用现有 `DATA_DIR`，因为缩略图仍落本地；图床原图不写入该目录。
- 建立一个共用原图存储边界，负责写入、读取、元信息检查与删除；local 和 imgbed 各有实现。保持数据库发布与原图后端职责分离，不到 HTTP handler 中散落模式分支。
- 未初始化时 runtime 能正常建立并提供 setup，不构造“默认 local”原图后端。
- 服务端内部读取完整存储配置，管理 API 仅使用脱敏视图；普通 `ReadSettings` 不读取或暴露 Token。
- 对图床上传、读取、删除分别设置网络超时；不能让已有数据库 15 秒 operation 超时意外限制完整上传。每次 DB 阶段保留 DB 超时，完整原图操作有独立 60 秒预算，父请求取消始终优先。
- 本期仍是单实例；不扩展多实例或跨进程图库锁支持。

## 7. 图床上传契约

### 7.1 请求

`POST {imgbedBaseUrl}/upload`，`Content-Type: multipart/form-data`，`Authorization: Bearer <Token>`。

固定 query：

```text
serverCompress=false
returnFormat=full
uploadFolder=agnes-image-proxy/YYYY-MM-DD
```

- 不提交 `authCode`、`expire`、`responseFormat` 或额外渠道选择参数，使用文档默认数组响应与服务端渠道选择。
- multipart 只有文件字段 `file`，文件名使用当前候选 publicID 加经验证 MIME 对应的扩展名，part Content-Type 为真实 MIME。
- 日期在开始上传时按固定 UTC+8（中国标准时间）生成一次，不依赖服务器本地时区或系统时区数据库；跨中国时间午夜、同一请求的后续阶段不改变已生成目录。该规则只决定上传目录的日历日期，签名 Unix 时间戳与数据库绝对时间语义不变。
- 原图仍限制为 PNG/JPEG/WebP、非空、最大 64 MiB。采用普通上传，不做客户端分块，图床渠道必须能承载相应体积。
- 上传请求不自动重试，避免网络结果不确定时重复上传；图床自身的渠道重试行为由其默认配置决定。

### 7.2 响应与身份

仅接受 2xx、受限大小（最多 1 MiB）的合法 JSON 数组，数组必须恰好一项，且含非空完整 `src`。允许对象内出现文档的其他字段，但不使用 `publicUrl`、短链接或 HuggingFace 特有响应作为替代。

- `src` 必须为配置站点同 origin 的 HTTPS URL，路径形如 `/file/{fileId}`，无凭据、query、fragment。
- 提取并逐路径段解码 `{fileId}`，拒绝空路径段、`.`、`..`、反斜线、控制字符、编码后路径逃逸等；必须处于本次 UTC+8（中国标准时间） 日期目录内。
- 持久化相对 file ID，而不是固定绝对 src；读取/删除按当前站点地址重建路径。地址变更因此只适用于同一套文件或等价迁移站点。
- 图床返回明确 `expiresAt` 表示非永久文件时，不能当作可靠永久原图交付；拒绝交付，已获安全 file ID 的候选按确定未发布的规则尽力清理。
- 没有 `expiresAt` 并不能证明图床管理员未配置过期；部署文档要求关闭自动过期，程序不额外发未获批准的 `expire=forever` 参数。

### 7.3 成功标准

收到上传成功响应后，从 `/file/{fileId}` 读取一次原图，验证 MIME、字节数及字节内容与上传内容完全一致，再发布图库记录。未通过验证不返回交付成功。

该校验用于确保“原图存储”而非仅收到链接，避免服务端变换、规则拦截或返回不可访问文件。初始化不做真实上传验证，因此首张生成可能因 Token、渠道或防盗链配置错误失败。

新原图发布成功后，`b64_json` 可使用刚验证一致的内存内容，不额外再下载一次。output key 已存在时使用已有原图记录和已保存内容，不用新候选内容替换已保存原图。

## 8. 读取、签名、参考图与富化

- `GET /v1/images/content/{publicID}` 保留现有签名验证、过期边界、统一 404、no-store、Content-Disposition、nosniff 和 sandbox；通过后端取得原图字节，不向客户端 302 到图床。
- `HEAD` 不读完整原图。local 保留文件 stat；imgbed 对 `/file/{fileId}` 发 HEAD 验证存在与 MIME，远端提供长度时核对。远端不提供长度时使用已验证保存的数据库字节数，不用 GET 伪装 HEAD。
- imgbed GET 有最大 64 MiB 限制，核对保存的 MIME/字节数并验证图片签名；错误、超时或内容不符不回源 Agnes、不回退 local、不使用数据库原图 BLOB。
- 图床文件真正不存在返回现有 not_found；403、网络错误、5xx、MIME/长度错误属于存储不可用，对签名端点为 503；禁止将权限问题伪装成不存在。
- 管理员原图下载使用相同原图边界，不受图片 TTL 影响。
- 本程序签名 URL 作为参考图时继续先验签、从原图存储读取后转 Data URI，不自请求 HTTP、不将 Token 转交客户端或 Agnes。
- 富化继续优先 Agnes source URL，失败时从已保存原图读取做一次受现有预算约束的 base64 回退；不把图床地址伪装成 Agnes source URL，不上传第二份原图。
- 图床普通文件读取不发送 API Token，不添加 `from=admin`、尺寸处理 query 或防盗链绕过参数。管理员需要允许代理后端正常读取这些文件。
- 图床原始公开 URL 可被独立访问；本程序签名只约束本程序入口，不能宣称其可撤销或隐藏图床公开副本。

## 9. 地址/Token 更新与并发一致性

存储方式在持久化 API 和服务端验证中共同固定，不能仅靠前端禁用。

每次完整原图生命周期取得一个不可变的配置快照；上传、回读、候选清理不得混用更新前后的地址或 Token。存储配置更新与正在进行的原图操作通过同一生命周期读写协调：更新等待现有操作结束，成功后新操作使用新配置，不要求重启。

协调范围包括交付发布、原图读取、单删、清空和连接信息更新；锁顺序必须一致，避免和 gallery gate、output/image locks 死锁。长网络操作有超时，等待更新可取消；不要长时间持有数据库事务或连接去等待网络。

更新不改 existing file ID/publicID，不延长/撤销已有签名，不迁移内容，不保留旧连接 fallback。换到无对应文件的站点会导致旧图不可读，这必须在页面和文档明确提醒。

## 10. 删除、清空及数据库重建

### 10.1 原图后端删除

- local 沿用应用自有文件清理。
- imgbed 使用 `GET /api/manage/delete/{fileId}`，携带 Bearer Token，逐段编码 file ID。
- 必须检查 2xx 及 JSON `success: true`；`existed: false` 是幂等成功。200 中 `success: false`、权限错误、超时等均算失败。
- 不调用整站清理、日期文件夹递归删除、文件列举或任意用户提交路径。仅删除图库所记录的安全 file ID，以及确定未发布的本次上传候选。

### 10.2 单删

持有现有图库/图片生命周期协调，先确认数据库行及原图定位，再删除原图，远端成功后删除对应数据库行和本地缩略图目录。

原图删除失败时保留行和定位，返回 503，使管理员可重试；数据库删除失败时保留行，允许重试远端幂等删除。不要先丢失唯一远端定位再尝试网络清理。

网络请求和 DB 删除不是分布式事务：远端已删除而 DB 未删期间该记录暂时不可读取，此限制明确披露。缩略图清理失败仍报错，不声称完全删除。

### 10.3 清空图库

持有 gallery 独占生命周期，阻止新发布、并发删除及配置更新。推进 gallery generation，保留已有的不确定晚提交隔离规则。

- 按有界页读取记录，执行与单删相同的原图/行清理，不将整个图库或文件列表一次载入内存。
- 已成功删除的记录可消失；某条失败则保留该条和未处理条，停止并返回 503。UI 文案说明清空可能部分完成，重试继续清理。
- 所有记录清理成功后才清理本地应用候选/缩略图文件。
- 不对图床 `agnes-image-proxy` 文件夹做递归清理；该目录可能由其他部署共用。

### 10.4 reset-db

保留“先停服、显式 --confirm”的安全前提，不带确认不得读配置或打开资源。

- 旧 schema 按用户允许的破坏性升级直接重建，不尝试理解旧原图数据，不添加迁移/旧后端清理逻辑；现有本地应用目录仍按明确 reset 契约清理。
- 当前 schema 4 如已选 imgbed，先使用当前配置清理图库已登记远端原图，成功才丢弃包含 Token/file ID 的应用表并创建未初始化 schema 4。
- 当前图床清理失败则命令失败并保留配置/剩余记录，不继续删除清理凭据。部分记录可能已成功删除。
- 重建后存储配置无记录，重新进入初始化，可再次选择方式；这不是运行中切换。
- 不保证清理远端孤立候选，不接触未登记的第三方文件。

### 10.5 不确定结果

保留现有原则：DB 提交结果不确定时不能删除可能已经被引用的候选。确定冲突复用时清理未引用新候选；能确认未发布的候选可以尽力删除。超时/崩溃可能留下图床孤立文件，本期没有远端 GC 或补偿任务队列，不为此新增冗余存储。

## 11. 网络与秘密安全

- 图床地址必须为 HTTPS origin，禁止路径（允许并规范化末尾 `/`）、query、fragment、userinfo、异常端口；主机/默认端口规范化。生产要求公开可路由地址，不开放任意内网或 HTTP 图床支持。
- 使用受控 DNS 与拨号，防止请求被 DNS 重绑定带向私网、loopback、link-local 等保留地址；不让环境 HTTP proxy 绕过这些校验。测试使用注入 transport，不放宽生产规则。
- 上传、删除请求不跟随重定向，避免 Token 或请求体跨站泄露；图床部署必须提供最终站点地址。
- 公开读取允许至多两次 HTTPS 重定向，每跳及实际拨号均做网络边界检查，不携带 Token。无需扩展现有参考图 SSRF 权限。
- Token trim 后非空、最多 4096 字节，无控制字符；仅在受鉴权 POST/PUT 请求体进入，后端内部传递。
- 日志和返回错误只描述操作/类别/状态码，不输出 Authorization、完整配置、Token、原始远端正文或含凭据的 URL。
- 数据库凭据、数据库备份和管理员权限需按含密钥资源保护；不宣称本项目具有多用户权限隔离。

## 12. 验收与测试

### 初始化/配置

- 空库无默认策略；未初始化可以登录/setup；数据面和其他管理操作门禁有效且不调用上游。
- local/imgbed 初始化正确，非法/未知/冲突字段拒绝；并发初始化唯一成功。
- 重启保持配置；普通 settings PUT、storage POST/PUT 均不能切换模式。
- 图床地址/Token 更新原子生效，空 Token 保留，明文不出现在管理响应或日志。
- schema 4 正常运行，旧 schema 拒绝普通启动，无迁移、旧字段 fallback。

### 图床 HTTP 客户端

- multipart 文件内容、MIME、Authorization 和三个固定 query 准确，UTC+8（中国标准时间） 日期边界可注入测试。
- 完整 src/文件目录验证、URL 编码、单项数组、响应限制、到期文件拒绝。
- 上传后回读完全一致才发布；变换、403、无效图片、截断、超限、超时、取消不交付成功。
- 上传不盲目重试；不转发 Token 到重定向或公开文件读取。
- HEAD 无 GET/body 下载，长度存在/缺失/不符分支覆盖。
- 删除 HTTP 200 逻辑失败、缺失幂等、403、网络错误覆盖。
- 公共 DNS/拨号/重定向 SSRF 限制有测试，不使用真实图床或真实 Token。

### 生命周期集成

- 两种策略均可生成、签名 GET/HEAD、管理下载、b64_json、签名参考图复用及富化回退。
- imgbed 不写本地原图；local 不发图床请求；缩略图功能保持可用。
- 重复 output key 不替换原图，返回已有原图内容；不确定 DB 提交不会删除潜在有效候选。
- 上传与删除/清空/配置更新相互协调；测试更新跨越上传回读时不混用站点或 Token。
- 删除失败可重试，清空部分失败保留定位；reset 未确认无副作用、清理失败不丢 Token。
- preview 显式初始化 local 后播种演示数据，保持完全离线；不借 preview 加入生产默认初始化分支。

### 前端与交付验证

- setup 登录/未初始化/已初始化守卫、两种选项、条件字段、禁用/提交/错误状态、成功跳转。
- 设置页只读方式、Token 不回显、空值保留与更新失败提示。
- API/Zod/OpenAPI 契约同步；更新现有 fixtures，不保留旧响应解码。
- Go 全量测试（包括可用的 race 测试）、前端类型检查/测试/生产构建、格式检查与现有仓库检查通过。
- 更新 README 的初始化、升级 schema、备份、图床权限、永久文件要求、地址变更与删除部分完成说明。
