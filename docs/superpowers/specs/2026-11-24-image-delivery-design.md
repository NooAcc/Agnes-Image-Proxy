# URL/base64 统一图片交付设计

日期：2026-11-24
状态：待用户确认；此文档不是实施授权。

## 1. 目的与已确认约束

程序已迁移 Docker，允许打破过去 URL 优先造成的链路限制，但仍保留 Edge-Images，以减少代理自身的图片处理负担。

用户已确认：

- Agnes 固定请求 URL 输出，与客户端返回格式解耦。
- 原图下载、校验并保存完成后才向客户端返回成功。
- 客户端 URL 指向本程序保存的原图，不再直接暴露 Agnes 链接。
- 客户端仍可请求 `b64_json`。
- Edge-Images 继续负责尺寸测量、缩略图和 NSFW。
- 客户端图片 URL 默认 TTL 为一天，可在设置页修改。
- 不兼容旧代码或旧数据，不增加迁移、旧字段映射或多格式兜底分支。

沿用 Go + React、Turso/libSQL 原图 BLOB 存储、现有账号池和受控下载器。不引入对象存储、Docker 文件卷、图片处理库、持久化任务队列或新的外部服务。

## 2. 对外协议

### 2.1 生成与编辑

保留 `/v1/images/generations` 和 `/v1/images/edits`。

客户端唯一的输出格式入口为 `response_format`：默认 `url`，可选 `b64_json`。删除客户端 `return_base64` 别名；显式传入时返回 400 unsupported_parameter，不静默忽略。`extra_body` 中的输出格式控制参数也应拒绝，不提供另一套优先级。

每个响应图片只包含所选格式的非空字段，另一个字段省略。继续保留现有 created、size 和 revised_prompt（如仍需占位）的响应语义；不凭空编造上游修订提示词。暂不增加多套图片详情返回接口。

- URL 输出：`url` 为完整绝对签名地址。
- base64 输出：`b64_json` 为标准、带 padding 的裸 base64，不带 Data URI 前缀。与保存的原图逐字节一致，不缩放、不转码。
- 任何返回成功的图片均已经存在于图库原图存储；base64 请求也保存原图。

### 2.2 图片访问

新增独立图片内容端点，建议 `/v1/images/content/{publicID}?expires=...&signature=...`。

- GET 和 HEAD，无需附带 Bearer 或 Cookie；仅有效签名授权。
- 签名授权仅访问指定原图，不授权图库列表、删除、设置或管理操作。
- HEAD 验证授权和图片存在性，但不返回正文；应尽量查询元信息而非传输完整 BLOB。
- 返回真实 MIME、长度、正确后缀的 Content-Disposition，保留 nosniff 与 sandbox 防护。
- 访问授权以服务端时钟为准，`now >= expires` 即无效。
- 无效、过期、篡改或图片不存在使用统一 404，不泄露图片是否存在。验证签名、参数格式、到期时间在数据库访问之前完成。
- 明确返回 `Cache-Control: no-store`，防止浏览器/CDN 在 TTL 到期后通过缓存继续交付。TTL 无法撤回客户端已经下载保存的副本。
- 有效签名图片响应可复用已有允许来源的非凭据 CORS 策略；OPTIONS 仅做预检，不绕过 GET/HEAD 的签名认证。
- 管理图库仍使用现有 Cookie/Bearer 认证读取原图，不受签名链接 TTL 影响。

### 2.3 TTL 与地址设置（实施者建议，待确认）

新增设置：

- `imageUrlTtlHours`：整数小时，默认 24，可选 1–720（最多 30 天）。前后端与 OpenAPI 同一范围。设置页中文名称“图片链接有效期（小时）”。
- `imagePublicBaseUrl`：可选公网基础地址，默认空。用于指定 Docker 反代后的外部 origin，例如 `https://images.example.com`，不接受路径、查询、片段、凭据；仅本地回环可用 HTTP。

基础地址为空时，沿用现有可信反代规则，从请求 origin 推导地址：只信任 TRUSTED_PROXY_CIDRS 内的 X-Forwarded-Proto/Host；非可信来源不采用转发头。验证最终 scheme/host 后才能签发。显式基础地址不依赖请求 Host，适合正式部署。

TTL 从 HTTP 响应签发链接时算起，而不是 Agnes 开始生成时。更新 TTL 只影响以后签发的链接，不重新解释已有 expires；不删除原图、不延长旧链接。图库删除/清空使相应链接立即失效。

图片链接使用 PROXY_API_KEY 作为根密钥，采用独立领域标记的 HMAC-SHA256 签名，不复用管理会话 token 格式。签名覆盖固定用途、随机 publicID 和 expires，常量时间验证。密钥轮换使所有旧图片链接失效；撤销管理会话不影响图片链接。不得把 API 密钥、签名 URL 写入应用日志。

图库每行增加随机 128-bit 或以上 publicID（唯一约束）。签名不只依赖自增 id，避免清空图库后数字 id 重用导致旧链接访问新图片。数据库 schema 版本递增，不兼容旧库，启动拒绝旧版本并给出现有 reset-db 指引；实施不实际重置生产数据库。

## 3. 内部统一链路

### 3.1 Agnes 适配

输出格式恒定 URL，不读取客户端 response_format 来决定上游格式。

保留 `imageParamMode` 的 nested/top_level 参考图参数位置配置：这是当前 Agnes 适配边界，不因删除客户端 base64 输出分支而顺便删除。

在两种参数位置、有/无参考图场景明确构建 URL 输出请求。只接受上游契约中的非空、无凭据 HTTPS URL；预览测试环境可通过已有注入边界使用 loopback HTTP。上游只返回 base64 时视为 invalid_upstream_response，不新增“自动再生成另一种格式”逻辑。

确认真实 Agnes 行为需要真实额度/凭据，不在未授权情况下执行联网生成；以现有文档和 mock 断言验证本地请求构造，最终报告明确这一验证边界。

### 3.2 下载、校验和持久化

每个执行中的子请求依次：账号池生成 → 下载 → 轻量类型/体积校验 → 原图保存。

- 复用 SSRF-safe 下载器：HTTPS、公开可路由 IP、重新校验重定向、连接到已经校验的 IP、超时和最大图片体积。
- 不完整解码图片，不缩放、不转码、不做本地 NSFW。PNG/JPEG/WebP 类型识别保持一致。
- 下载最多有限重试（建议最多 2 次，仅临时网络/429/5xx，不重试类型错误、超限、SSRF 拒绝等确定性失败），复用同一源 URL，不再次调用 Agnes。持久化失败不换账号重生。
- 并发许可覆盖整个生成/下载/保存阶段，而不只覆盖 Agnes HTTP 调用，防止生成并发受限但下载/保存无界。
- 单图片字节预算与下载上限一致（现有 64 MiB）；不因为 Docker 就取消限制。请求级容量/输出总字节仍不声称严格有界，文档明确多图 base64 会占较多内存。
- URL 客户端响应不持有用于交付的 base64 字符串。base64 仅由已下载数据编码一次。保存完成后后台任务尽量只携带图库 id/来源元信息，不携带整批原图。
- 不再在原图保存失败时退化成“无原图的成功记录”。只保存已下载、校验通过的原图；数据库失败明确进入交付失败统计。
- 已保存图片不会因客户端断开而删除。对已有已保存图片尽力安排富化；客户端取消停止新的生成/下载，不补发其余 n、不无限脱离请求执行下载。已有成功输出及任务预留必须被释放或提交一次，避免取消/关闭泄漏。

上游账号成功计数仍表示 Agnes 生成成功，不因下游存储失败把账号降为不可用；客户端请求成功计数改为图片交付成功。两者含义在文档说明。

### 3.3 聚合响应与错误

继续保持有序、受控并发与部分成功。

- 返回图片列表只含已经成功保存的输出，按子请求和子输出顺序排列。
- `X-Agnes-Succeeded`：至少有一张图片成功交付的子请求数；`X-Agnes-Failed`：没有任何交付成功的子请求数；合计仍为 Requested。
- 一个子请求多个输出中只保存了一部分，也添加 partial-success 警告，即使 Succeeded 为 1、Failed 为 0。响应图片数和日志 Images 按实际交付数计算。
- 下载失败为可识别的 502 交付错误，超时为 504；持久化失败遵循现有数据库不可用 503。
- 保留全失败的现有优先级 429 > 504 > 502 > 503；新增阶段错误参与同一聚合，不把下游失败错误归入账号尝试冷却逻辑。
- 日志尝试仍是 Agnes 账号尝试。额外阶段失败写出可定位的 stage/code 摘要（不包含源 URL/query、签名或原图）；具体 DTO 的最小扩展由实施者决定，不能把错误吞成空图片。
- 一张原图保存失败不影响其他成功输出，不回滚整批成功图片。

## 4. Edge-Images 分工

保留并优化现有 Edge 元数据、富化、手动补齐功能。

- 尺寸测量继续通过 Edge-Images，同步 best-effort 批量读取尺寸，不能因为测量失败就把已保存原图当作失败。未配置服务时维持现有预计尺寸行为，不悄悄变成本地图片处理。
- 缩略图和 NSFW 仍在响应后后台执行。同步阶段只保存原图；任务类职责调整为富化，而不是重复下载和保存原图。
- Edge 优先取 Agnes 源 URL，避免本程序把原图编码、上传到 Edge。
- URL 在 Edge 的 fetch 失败且有本地原图时，仅失败项允许一次 base64 重试。按需从图库加载原图，并正确填写 contentType。
- 同步尺寸测量继续 best-effort URL 请求，不为测量失败再加载并上传整张原图；后台富化/补齐的 base64 容错不等于旧数据兼容。
- 修复纯内联首轮以及重试批次的预算计算：所有实际发送 base64 的项都计入预算；按数量与字节双重分批，限制单图，明确原图字节和 base64 膨胀成本。
- 遵守现有 Edge 每批最多 20 项、32 MiB 原图字节批预算（加上 base64 膨胀后设置实际请求长度上限）；超过批预算但未超过单图上限是否单独发送由实施者根据 Edge 契约决定并明确测试。不得形成“允许 50 MiB 但所有大于 32 MiB 图片都没有明确信息”的静默失败。
- Edge 不可用不影响已持久化原图的交付，失败状态可在图库中观察、手动补齐。
- 不向 Edge 发送本程序的签名 URL，仍用 Agnes URL 或按需 base64，避免额外读取 Turso 及签名 TTL 耦合。

## 5. 参考图输入闭环

保留 URL、Data URI、multipart 三种当前输入形式，不增加裸 base64 自动猜测。

- Data URI 与 multipart 做一致的真实 MIME/支持类型校验，拒绝声明类型不匹配、无效 base64、非图片、超限。尽量统一解码帮助函数，避免反复解码。
- 客户端拿本程序有效签名 URL 再做参考图时，可用。识别自己签发的内容端点，先验证签名与 TTL，再从图库按 publicID 读取原图，转换成标准 Data URI 传给 Agnes。auto 尺寸读取沿用现有参考图本地头解析能力，不请求自己 HTTP 服务，避免 Docker loopback/内网 URL 的 SSRF 阻挡与额外数据库读取。
- 只针对精确匹配本程序配置/当前可信 origin 与固定内容路径的链接做本地解析；其他域名 URL 不按本地图库地址解释，不放宽通用 SSRF 下载规则。
- 本程序过期/篡改/已删除图片参考返回 400 image 参数错误，不把未经认证的图片 id 当作读取权限。
- 外部参考图仍沿用现有转发/自动尺寸逻辑与安全边界。
- 16 张、单图 20 MiB、请求体 32 MiB 的输入限制不变。本地 signed URL 展开后的累积 Data URI 体积也必须受 32 MiB 的规范化输入预算限制，不能用短 URL 绕过内存/上游请求预算。

## 6. 管理控制台与文档

- 设置页按现有表单风格添加 TTL 与可选公网地址字段，错误反馈和 schema/OpenAPI 保持一致，不重新设计页面。
- 图库读取存储 BLOB，来源格式不再影响可查看性；正常生成记录均有原图。
- 下载文件名使用原图实际类型，不固定 `.png`；最简单可由服务端 Content-Disposition 决定，而不是浏览器强制错误后缀。
- 清理仅元数据成功归档相关旧逻辑、内部上游 Base64 输出分支、无用接口/测试，不能留下已死的默认兜底。
- README 解释签名链接 TTL、设置更新/密钥轮换/删除效果、同步持久化时机、Edge 分工、源 URL 与客户端 URL 的区别。
- 明确 schema 升级必须新库或显式 reset-db；不执行用户真实数据删除。
- Compose 只读根文件系统/无数据卷保持不变，公网地址与可信反代配置给出示例。

## 7. 验收

以离线 mock 为主，所有重要分支加测试：

1. 无参考图/有参考图、nested/top_level、客户端 URL/base64 的组合，上游始终请求 URL。
2. HTTP 响应只含所选非空格式；base64 解码与图库原图、URL GET 正文完全一致。
3. 返回成功前原图已保存；新签名链接立即可访问；GET/HEAD MIME、长度与下载后缀正确。
4. 默认 TTL 24h，设置更新、新旧链接有效期、到期边界、字段篡改、路径/publicID 替换、重复/非法查询参数、密钥轮换、删除/清空后 id 重用均验证。
5. 未授权请求不读 BLOB、不访问管理接口；过期链接不被缓存继续交付。
6. 显式公网地址、直连、可信/非可信转发头的 URL 构造与字段校验。
7. 下载失败/超时/存储失败的全部和部分交付，n/图片/账号计数、顺序、日志、不再次生成、不重复保存。
8. 并发、任务容量、取消、响应写失败、优雅退出，不丢已保存图片、不泄漏任务预留。
9. Edge 优先 URL、关闭/失败不阻断交付、后台 base64 一次重试、纯 base64/混合批次的数量与字节预算、按需加载原图。
10. 参考图输入 Data URI/文件一致校验，本程序 URL 再输入、TTL 失效、自动尺寸、外部 URL 和规范化预算。
11. 设置读写、严格 schema、共享前后端契约 fixture、前端 TTL 表单/下载测试。
12. 全仓 go test、go vet、前端 typecheck/lint/test/build；环境支持时 race 与既有 e2e。真实 Agnes/Turso/Edge 验证未经另行授权不执行，也不声称已通过。

## 8. 交付与边界

这是跨服务、HTTP、存储与前端契约的项目级变更，确认设计后编写分阶段实施计划。

本设计中 TTL 整数小时范围、公网基础地址设置、no-store 策略、随机 publicID、客户端参数清理与本程序 URL 输入闭环均为实施者提出的具体选择，而非用户此前逐项指定；用户确认本设计后才实施。
